抓包字段逐层解析：Frame / Ethernet II / IPv4 / TCP

样本连接：本机 10.250.0.162:50771 → 14.17.83.246:443（取自 netstat -ano 的真实 ESTABLISHED 连接）
⚠ 本机未安装 Wireshark / tshark，且无管理员权限开启原始套接字抓包。按实验指南「未安装则提交说明」的要求，改用真实连接的 MAC / IP / 端口字段逐层展开协议头；其中 MAC 来自 ipconfig 与 arp 表实测，IP/端口来自 netstat 实测，序号与标志位为 TCP 首部的标准字段示意（需抓包软件才能读取实时值）。
Frame
帧		抓包概览接口：WLAN（F8-54-F6-60-88-06） · 帧长度：以太网最小 64 B / 典型 1514 B · 捕获时间：本机实时 · 协议：TCP / HTTPS
Ethernet II
数据链路层		源 MACF8-54-F6-60-88-06（本机 WLAN 网卡，ipconfig /all 实测）
目的 MAC3C-15-FB-A9-72-2F（默认网关 10.250.0.1，arp -a 实测）—— 发往外网时下一跳是网关，故目的 MAC 是网关而非最终服务器
类型字段0x0800 = IPv4（若是 0x86DD 则为 IPv6）
IPv4
网络层		源 / 目的 IP源 10.250.0.162（本机私有地址） → 目的 14.17.83.246（对端公网服务器）
版本 / 首部长度Version = 4 · IHL = 5（20 字节，无可选字段）
TTL64（Windows 主机默认值；每经一个路由器减 1，归 0 则丢弃）
协议号6 = TCP（17 = UDP，1 = ICMP）
TCP
传输层		源 / 目的端口源 50771（本机临时端口） → 目的 443（HTTPS 服务端口）
序号 / 确认号Sequence Number、Acknowledgment Number：用于按序重组与可靠传输（实时值需抓包读取）
标志位 / 窗口SYN / ACK / FIN / RST 等控制位；Window 用于流量控制
字段作用范围辨析（对应「常见问题」）：
• MAC（F8-54…/3C-15…）：只在同一链路内有效，每经过一个路由器就被重写一次 —— 本帧目的 MAC 是网关的，不是 14.17.83.246 的。
• IP（10.250.0.162/14.17.83.246）：端到端保持不变，标识源主机与最终目的主机。
• 端口（50771/443）：标识端到端的应用进程，443 说明这是 HTTPS 流量。
• HTTP 是应用层协议，不在传输层；DNS 也是应用层（UDP 53），二者都不属于传输层。
